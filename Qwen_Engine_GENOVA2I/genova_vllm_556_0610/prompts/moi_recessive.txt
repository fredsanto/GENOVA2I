TASK:

1. Both variants are jointly required to explain a recessive phenotype under
   this model — they are CO-CAUSATIVE, not competing. Do not rank one as

2. PM3 [Moderate, +2]: PHASE GATE FIRST, MANDATORY — PM3's own ACMG definition
   (Richards et al. 2015) is "detected in trans with a pathogenic variant";
   confirmed trans phase is part of the criterion itself, not a separate,
   skippable nicety. The Python gate above only blocks a confirmed CIS pair
   from reaching this stage — it deliberately still lets a pair with UNKNOWN
   phase through (no parental data to determine it either way), because that
   pair may still be reportable as two independent findings. Two sub-cases:

   (a) PHASE line reads "TRANS confirmed": PM3 applies normally as a firm
   criterion. Check each variant's partner's classification explicitly
   before applying PM3 to it — a partner that is only VUS or weaker does not
   support PM3 for the other variant even under confirmed trans. It is
   possible for PM3 to apply to both, one, or neither variant depending on
   each partner's own base classification. Classification is final/confirmed
   in this sub-case — use the ordinary labels (Pathogenic / Likely
   Pathogenic / VUS / etc.) with no hedge.

   (b) PHASE line reads "UNKNOWN" (singleton or unresolved trio, no way to
   determine cis/trans): PM3 [Moderate, +2] MAY be applied to a variant AS A
   HYPOTHESIS, but ONLY when its partner independently reaches Likely
   Pathogenic or Pathogenic on its own BASE CONCLUSION alone (before any
   recessive-layer points) — a weak or VUS-level partner still does not
   support even a hypothetical PM3. When applied this way: (i) label the
   criterion itself "PM3 (hypothesis — trans phase not confirmed)" in the
   criteria list rather than a bare "PM3"; (ii) the resulting total/label for
   that variant must read "Potential Pathogenic" or "Potential Likely
   Pathogenic" (never the bare, unqualified label) — this is a conditional
   classification pending phase confirmation, not a diagnostic one; (iii)
   this does NOT replace step 5's singleton recommendation below — a
   variant carrying a hypothesis-only PM3 still requires explicit advice
   that segregation/phasing testing is needed to convert "Potential" into a
   confirmed classification. An unconfirmed phase could just as easily be
   cis (both changes on the same chromosome copy, leaving the other
   parental copy intact — no biallelic disruption at all), which is exactly
   why the hypothesis framing and the "Potential" qualifier must both be
   preserved rather than silently upgrading to a firm call. A real past
   failure (illustrative — GENE_X standing in for whatever gene triggers
   this pattern): a variant with Allelic_balance_mother=0 and
   Allelic_balance_father=0 (i.e. apparently de novo, not inherited from
   either parent) was narrated as "inherited from mother, implied by the
   segregation pattern" — a fabricated genotype with no support in the
   actual AB data — used to manufacture a trans story and justify applying
   PM3 as if confirmed. A de novo variant's phase relative to a separately-
   inherited variant in the same gene is NOT determinable from trio
   allelic-balance data at all (a de novo mutation lands on a random
   chromosome copy, not deterministically on the one opposite an inherited
   allele) — this should have been "Phase: UNKNOWN" handled under sub-case
   (b) above (hypothesis PM3 + "Potential" label + recommendation), not an
   invented parent-of-origin used to grant a firm, unqualified PM3.

3. PP4 CONSISTENCY CHECK, MANDATORY: PP4 (phenotype-specificity) is a
   gene-and-patient-level fact, not a variant-level one — the patient's
   phenotype either matches this gene's known disease association or it
   doesn't, independently of which of the two variants you're looking at.
   Check both variants' BASE CONCLUSION "ACMG criteria:" lists above. If
   ONE variant's list includes PP4 and the OTHER's does not, and the
   omission is not explained by a variant-specific reason stated in that
   variant's own base conclusion (e.g. that variant sits in a domain/exon
   not linked to the patient's specific phenotype subtype, or the gene has
   two distinct disease mechanisms and this variant only supports one), this
   is an inconsistency, not a deliberate distinction — add PP4 [Supporting,
   +1] to the variant missing it, citing the same phenotype-gene match
   already justified for its partner. State this addition explicitly in
   that variant's "Recessive criteria applied:" line and include it in the
   "Base ACMG criteria" list for that variant (flagged as added at this
   layer, not silently merged into the copied-verbatim base list — see
   output format below) with its own point added into that variant's total.
   A real past failure (illustrative — GENE_X standing in for whatever gene
   triggers this pattern): Variant A of a compound-het pair received PP4
   because the gene's disease association matched the patient's phenotype;
   Variant B, same gene, same patient, same phenotype, did not receive PP4,
   with no variant-specific reason given anywhere in its base conclusion —
   an unexplained asymmetry that must not be reproduced.

4. State explicitly what evidence is present (or absent) supporting the

   expected recessive pattern. Do not invent this if the evidence is silent;

5. SINGLETON RECOMMENDATION, MANDATORY WHEN IT APPLIES: check both variants'
